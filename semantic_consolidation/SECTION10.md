# Optional scheduling, replay selection and inference controls

`route.extensions` adds three independently configurable components around the
existing joint classifier: explicit current/replay schedules, post-wake replay
ranking, and fixed-checkpoint ensemble/calibration evaluation. Omitting the
mapping retains ordinary joint fitting. All components target TensorFlow 2.20
and reuse the shared model, data, optimizer, sampling and reporting APIs.

## Module connections

| Component | Implementation | Existing API used |
|---|---|---|
| Configuration/lifecycle | `extensions.py` | Common configuration and task boundaries |
| Current/replay scheduling | `scheduling.py` | `DiffusionClassifier.fit`, existing optimizer and losses |
| Candidate scoring/selection | `replay_selection.py` | `q_sample`, `noisify`, `predict_class`, shared selection controls |
| Inference/calibration | `evaluation.py`, `evaluate.py` | `EnsembleAccuracy`, common probability metrics and checkpoint factory |
| Paired comparison | `study.py`, `controls.py` | `common.experiment`, complete-stream outcomes and source-bound manifests |

The common learner generates the candidate pool before its ordinary reduction.
The model adapter captures those exact sample outputs between completed task
fits. The extension checks the declared count, then ranks candidates only after
current-data updates. No additional candidate population is generated by the
selector. Selected labels are converted back to the wrapper's original-label
convention before fitting; dense classifier labels are used for scoring.

## Exact update schedules

`joint` delegates ordinary fitting unchanged. The other modes replace common
joint epochs with `wake_updates` current-only and `replay_updates` replay-only
full batches. Task one has no prior-task replay and uses only wake updates.

| Mode | Replay timing |
|---|---|
| `fixed` | Replay blocks after current-data blocks |
| `drift` | Defer a replay block below the JS threshold |
| `interleaved` | Alternate single current/replay updates until one budget is exhausted |

Every mode spends its remaining replay budget after the final wake block.
Consequently drift controls when replay happens, not how many replay updates
are purchased. Full batches cycle through seeded shuffled passes of each finite
pool. With an unchanged pool and seed, changing block boundaries preserves the
within-source presentation stream. Exact optimizer deltas and completed batch
counts verify each allocation. Early stopping and competing fit-budget overrides
are rejected.

Existing callbacks restart for each fit block. Validation runs on the final
block only. The same CE, diffusion and KD losses remain active according to the
common configuration and replay provenance. Equal updates and presentations do
not imply equal wall time or FLOPs: scoring, repeated fit setup, teacher passes
and different noising controls have separate costs.

## Drift and candidate quality

For one matched view, let `p` be the frozen old teacher's probability vector over
K old classes and `q` the current student's vector over all L seen classes.
The teacher is padded with zeros to width L; student mass on new classes is
retained. With `m = (p_padded + q) / 2`, the score is:

```text
JS(p_padded, q) = 0.5 KL(p_padded || m) + 0.5 KL(q || m)
```

Natural logarithms give a score in `[0, log(2)]`. Zero probability contributes
zero to KL. For multiple views the scorer averages per-view JS values; it does
not take the divergence of view-averaged probabilities. The teacher and student
receive the exact same image and stateless noise at each view. Both use null
CFG conditioning. The teacher is the prior-task checkpoint, not a newly frozen
copy of the post-wake student. Mean student probability on new-class columns is
reported separately as new-class invasion.

Noise level zero means an exactly clean image. Positive levels index the
existing diffusion schedule. Fixed candidate order, batch size and seed are
part of the protocol because changing batch partitions may change noising
streams. Deterministic latent inference is required.

The quality screen compares the teacher probability assigned to each generated
conditioning label against a fixed threshold. By default that threshold is a
quantile fitted once on generated training candidates. This measures teacher
self-consistency; it is not an independent visual-quality assessment.
`quality_fit_split: validation` instead fits on supplied old-class held-out
validation rows. An explicitly configured threshold records its declared
training/validation provenance and bypasses fitting. Test labels never fit the
quality rule.

| Strategy | Ranking statistic |
|---|---|
| `drift` | Higher matched-view prior/current JS |
| `random` | Existing shared seeded random ranking |
| `confidence` | Existing shared clean-teacher confidence ranking |
| `label_surprisal` | Existing shared clean-teacher conditioning-label surprise ranking |
| `mir` | Larger candidate conditioning-label NLL increase after a reversible actual joint update |

Every strategy uses the same base candidate scorer. MIR additionally performs
one virtual update with the existing optimizer, slots, clipping and losses,
then restores numerical model, optimizer and metric state. The virtual current
batch is prepared once with the actual training timestep/CFG context. This
preparation and virtual work are additional cost. MIR rejects EMA, mixed
precision, stochastic training layers, unprepared inputs and uninitialized
optimizer slots. The preview uses a bounded current batch; it does not claim to
predict the scheduler's exact next sampled batch.

## Row and class budgets

The common retained replay budget is B, and candidate generation must produce
exactly `B * candidate_multiplier` rows. The common and extension multipliers
must match. Common preliminary selection is restricted to all/uniform/random,
since the final ranking occurs after wake.

Strict quality screening never backfills with rejected rows or silently repeats
rows. `class_floor` reserves `min_per_class` rows per covered class, then fills
remaining slots by global rank. `fixed_per_class` assigns every class quota
before ranking, with a seeded score-independent remainder. Infeasible quotas
raise with available class counts rather than redistributing shortages.
Semantic phases require coverage of every old class and at least two distinct
positive row occurrences per class. Budget validation checks the largest old
class count, and the realized phase pool is checked before any gate update.
Distinct candidate occurrences may still contain identical pixels.

`reselect_each_wake: false` retains the first selected pool. Enabling reselection
changes both selection and scheduling, so it is a combined treatment. Drift
probes use the full fixed candidate population, independent of selected-pool
changes. Selection and final recovery records distinguish internal teacher/label
proxies from independent evidence of generative quality or causal usefulness.

## Configure and run

Start from `configs/extensions_smoke.yaml`, `configs/extensions_cifar10.yaml`
or `configs/extensions_cifar100.yaml`. The following fragment illustrates the
extension controls; the common fixed replay budget and candidate multiplier
must be configured consistently.

```yaml
route:
  extensions:
    schedule:
      mode: fixed
      wake_updates: 10
      replay_updates: 10
      batch_size: 32
      wake_block_updates: 5
      replay_block_updates: 5
      drift_threshold: 0.05
    replay:
      strategy: drift
      candidate_multiplier: 2
      batch_size: 32
      noise_levels: [0]
      quality_quantile: 0.0
      class_coverage: true
      min_per_class: 2
      quota_policy: fixed_per_class
    reselect_each_wake: false
    quality_fit_split: training
    evaluation:
      enabled: true
      horizons: [1, 4]
      noise_draws: 1
      batch_size: 32
      network_name: raw
      head_weights: [1.0, 0.0, 0.0]
      calibration_fraction: 0.5
      seed: 41
```

```bash
python -m semantic_consolidation --config semantic_consolidation/configs/extensions_smoke.yaml --dry-run
python -m semantic_consolidation --config semantic_consolidation/configs/extensions_smoke.yaml
python -m unittest discover -s semantic_consolidation/tests -v
```

The smoke configuration tests a small execution path; it is not a tuned
benchmark recipe. See [README.md](README.md) for paired full-stream preparation,
authenticated confirmation and complete task-matrix analysis.

## Fixed-checkpoint inference

Clean prediction uses the unmodulated primary head. Each optional ensemble
uses the existing `EnsembleAccuracy` implementation on the same chosen raw
checkpoint. Horizons are exclusive: horizon four evaluates schedule indices
0, 1, 2 and 3. Ensemble timestep zero is noised through the forward process;
it differs from the separate exactly clean reference.

Head weights refer to primary, distillation and regularizer branches and are
normalized before aggregation. `separate_probas` adds the existing candidate-
condition inference calculation; it is an inference-cost treatment, not a
training loss. Reports count classifier example-forwards and batch calls,
including the additional conditions, and record synchronized latency.

Optional temperature scaling fits one positive scalar on validation NLL for
each inference variant. An internal stratified split uses different calibration
and reporting rows, requiring at least two validation rows per represented
class. Test scoring requires separately supplied validation calibration arrays.
For an already mixed probability vector, scaling uses its log probabilities;
it does not change the individual head parameters. Predictive entropy is
reported descriptively and is not calibrated epistemic uncertainty.

```bash
python -m semantic_consolidation.evaluate --config results/run/config.yaml --split validation
```

Validation inference can explore explicit settings. Test access binds saved
route/data/inference settings to an authenticated confirmation manifest.
Checkpoint evaluation never invokes a training API.

## Artifacts and interpretation

`extensions.json` contains schedule allocations, realized presentations,
selection/quality records, prior-teacher invariants and inference results.
`ensemble_evaluation.csv` compares scalar metrics and work across requested
variants. The ordinary common continual matrices remain the primary endpoint;
post-schedule probes and inference variants do not replace them.

Report retained replay rows, candidate rows, class allocations, optimizer
applications, presentations, scoring/virtual work and inference cost separately.
Materialized array bytes exclude allocator overhead and are not measured peak
host/device memory. Optional measured resources and fixed-cohort diagnostics are
described in [EXPERIMENTAL_DIAGNOSTICS.md](EXPERIMENTAL_DIAGNOSTICS.md).
See [SECTION10_ASSESSMENT.md](SECTION10_ASSESSMENT.md) for verification boundaries.
